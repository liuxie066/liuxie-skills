# Devflow

`Brainstorm → Save Design → Improve Design → Impl → Review`

可单独调用一个节点，也可运行用户指定的节点序列。单节点完成后停止；已有有效输入直接使用，不为补齐流程重跑前序节点。只说“用 devflow”且任务或起点不明时先澄清。Implementation、Deepreview 分别映射为 Impl、Review。

整条流程由用户选择 `simple` 或 `full`：前者设计简短，后者展开重要取舍和失败场景；两者都保留五节点、四路设计建议及项目必需检查。根据实际行为风险推荐，用户已选则不重复问；单节点无需选择预设。

## 六条核心规则

1. **先确认要交付什么。** Brainstorm 展示原始目标、本轮范围、非目标和可观察的验收，再请用户确认。分阶段交付须明确本轮实现的效果、未覆盖的验收及后续安排。后续设计、代码或测试不能改写已批准目标；真实范围变更保留原依据并追加用户决定。
2. **设计建立在代码事实之上。** 从需求对应的真实入口读取相关源码、配置和测试，追到数据来源、决策与消费者；区分事实、推断和未知。文档与搜索命中只能定位。优先复用现有 owner、名称和实现；新建须说明现有能力为何不足。代码事实用于选方案，不能替用户重新定义目标。
3. **展示结果，再等确认。** workflow 每个节点完成后报告产物、验证、风险及下一步，记 `awaiting_user_confirmation` 并停止；用户看到当前版本后明确确认才能推进。预先的“完整链路”“一直做完”和旧版本批准不能代替。修改后重新展示；Review 通过后也须确认才标 `completed`。单节点到此交付，不借确认扩展到下一节点。
4. **改动受已批准范围约束。** 实现、验证、审查复用同一任务工作区和基线；保护他人改动。计划外修改须有已批准验收失败或具体安全缺陷的证据，普通整理和 reviewer 建议不是扩范围授权。目标、契约或权限改变时返回责任节点请用户决定。
5. **用业务结果证明完成。** 从真实入口验证已批准的可观察结果；配置能写入、build/status 正常不能单独证明业务功能生效。测试覆盖改动的成功与必要失败路径，并保留项目门禁；仅在相关内容、输入、依赖、基线和环境未变且原证据可回读时复用检查。
6. **研发与交付分开。** commit、push、PR、merge、release、upgrade 和生产写入各按用户授权及项目流程执行，不由 Devflow 自动附带。读取当前节点适用的 AGENTS.md；未获授权的副作用不因流程推进而获得授权。

## 各阶段产物

| 阶段 | 必要输入 | 交付内容 |
| --- | --- | --- |
| Brainstorm | 需求、现状与约束 | 已展示并待确认的目标、范围、验收、取舍和未知项 |
| Save Design | 已确认目标和方案 | 唯一设计文档：代码依据、改法、owner、数据/失败语义、行为切片与验收方法 |
| Improve Design | 完整设计及已批准范围 | 四份独立建议、采纳裁决、修订后的同一设计及必要检查结果 |
| Impl | 已批准设计、实现授权、工作区/基线 | 范围内改动及实际验证证据 |
| Review | 完整任务改动、原需求/授权及验证证据 | 只读审查报告：覆盖、结论、缺陷和剩余风险 |

### 设计与优化

Save Design 写入前补齐影响关键决策的代码证据，记录入口、owner、消费者及相关路径。沿用仓库现有文档 owner；新增概念、名称或实现只需说明“复用哪个 owner”或“为何新增”，证据不足保留未决，不开放式扫描全库。可选用 `scripts/reuse_scan.py` 定位候选；截断或未命中不能证明不存在。

设计应让实现者无需猜契约或重做关键选择。按可验证的行为增量切片，默认不超过三片，更多时说明理由；每片对应验收和依赖，所有验收均有去向。配置控制业务行为时，设计写清操作入口、实际消费者、输入、结果观察位置和预期；Impl 用能区分开关两态的数据，从真实入口验证变化与应保持的行为，留下预期与实测结果；Review 对照同一验收核查证据。

Improve Design 使用四位原生 subagent，容量不足时分批。向每位提供相同完整设计快照、绝对路径、目标/验收、相关代码及只读边界，独立回答：

> Any suggestions to improve this design?

- 不预分配专项角色，不提供主 agent 偏好的改法或其他 reviewer 的结论；reviewer 定点读所依赖代码，返回位置、证据/假设、建议、收益代价和未覆盖项。有依据的“无建议”有效，不要求 pass/fail，也不自行运行 Planreview。
- 主 agent 直接派发；有跨模型家族能力时使用，逐位记录实际可验证的身份和独立性，未知则如实说明。四份结果不能相互替代，自审不能算独立结果。
- 主 agent 核证、去重并说明采纳、拒绝、延期或待补证据。展示拟采纳改法及影响，**等用户确认后**合批修订同一设计；改变行为或数据流前补读相关代码。最终设计仍须经过节点确认才进入 Impl。只读请求只交付建议。
- Planreview 仅在用户/项目要求或有明确重要设计风险时运行；不因 `full` 或结构调整固定加审查。可在已批准方向内合批修订后重审；新范围或权限决定须暂停。旧 Panel 结果绑定旧快照，不能称其已审过修订版本。

Save Design、Improve Design 的主 agent 与 Impl 使用可用 ponytail；Review 使用 deepreview；文档遵循仓库约定，OM 使用可用 om-doc-hygiene。只加载当前所需 skill。缺失时披露并执行同等必要检查，不自动安装，也不伪称执行过该 skill。

### 实现与范围

进入 Impl 前核对 Git 状态、worktree、任务归属及目标基线。新任务刷新并核验目标远端引用；固定历史基线遵从用户选择，离线时不称旧引用为最新。保护分支、共享工作区、无关脏改动或并行冲突需要隔离，优先复用合适的专用 worktree。设计阶段只作只读决策，进入 Impl 且授权充分后再执行；不重复询问普通可逆隔离选择，不自动 stash/reset/rebase 或搬动他人文件。

记录初始工作区、base/HEAD 和已有改动的实际内容依据，后续不覆盖初始基线。每片结束及 Review 前检查完整任务 diff，包含 committed、staged、unstaged、untracked、新增/删除/重命名和模式变化；新增文件须读正文。用初始范围判断归属，只移除明确属于本 agent 的越界改动，归属不明先询问。删除或退役前核对真实消费者，包括动态注册、exports 和相关测试。

每片先明确对应验收，再实现和针对性验证；普通编译/测试失败可在当前片内修复。片尾展示行为、验证和偏差，等用户确认后才开始下一片。最后一片与项目最终验证合并为一次 Impl 结果确认，再进入 Review。事实与设计不符时说明差异，不削弱验收；需要改变已批准设计决定时返回设计节点。

### 审查与返工

Review 只审查，可写报告，不修改代码、测试或设计。核对原始批准及合法变更，对正确基线下全部当前任务改动走读，沿真实入口检查行为、失败路径、owner 和验收证据；重审也覆盖完整改动。没有正式设计的独立 Review 可依据真实需求开展，不补造设计批准；影响结论的缺口须明确。

- 有证据且未关闭的严重、高、中问题阻止通过。调用失败、材料缺失/截断、矛盾结论或重要覆盖缺口均不可算通过；低风险说明影响、责任和后续去向。
- workflow 的代码返工顺序为：**Review 结果 → 用户确认 → Impl 修复与验证 → 用户确认 → 再次 Review**。设计缺口回 Improve Design，目标/范围变化回 Brainstorm，同样经过结果确认。单独 Review 只交回报告和建议。
- 适用的 Planreview、Review 各最多五次调用尝试，失败也计数，返工或恢复不清零；第五次未通过即停止。合批处理已知阻塞项、完成验证且材料可读后才重审，不对未就绪版本重复派发。
- Panel 每位失败最多补一次独立重试；仍缺结果或无 subagent 时报告实际独立覆盖（如 0/4）、缺口及未覆盖风险，并停止。自审只能提供建议，不能补足四份结果；用户明确接受降低覆盖后才继续，并按实际覆盖交付，后续结果确认照常。等待中的任务先查询原句柄，观察超时不另派任务。

## 最少记录与恢复

沿用一个任务记录；已有 `.devflow/scope.md` 就继续使用，没有则在首次获准落盘时建立。只记恢复所必需的信息：原目标/验收与用户确认、设计路径及内容 hash、工作区/初始基线、当前节点和待确认结果、下一步、验证/审查证据、尝试次数及运行中的任务句柄。设计正文留在唯一设计 owner，不复制进状态文件；不要求固定 YAML 模板或额外逐文件台账。是否跟踪记录遵循仓库约定。

单独 Brainstorm 不自动写文件；需要交接时保留简短摘要。恢复先核对已确认版本及未完成决定，无法证明确认则继续等待。仍有效的完整证据可复用，只有摘要或 hash 不足以替代原文；保留真实命令退出码和可读证据，不能把进程已派发或日志末尾成功当作完成。

各节点报告实际产物、验证和限制。研发收尾提供设计版本、实现范围、Review 结论及风险，供用户另行授权 Delivery；不另设收尾节点。
