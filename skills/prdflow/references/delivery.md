# 产物与交接约定

用于首次成稿、修订、收口、保存、恢复上下文或准备 devflow 交接；不是每轮对话的固定输出格式。

## 先交付可读草稿

成稿请求应得到当前完整正文。未保存时在最终回复呈现，已保存时链接实际更新的文档。
草稿可包含待确认建议、未知事实和局部阻塞，逐项注明影响；成稿不等于已确认或可交接。
综合已有讨论不授权替用户补定产品选择。新增选择逐项标为建议，对应验收也标待确认；
不能只在开头写“草稿”或“默认”，随后把建议混入已确认规则。
用户要求更新既有文件时，修订原文件正文、受影响验收并追加本次确认依据；仅要求整理讨论而未指定落盘时先交付会话版，不为保存再加一轮问答。
普通解释或局部讨论只展示必要变化，首次成稿和整体收口不能用摘要、门槛 JSON 或工具输出代替正文。

## 一个需求 owner

先查现有文档与项目约定。已有需求文档就更新同一份；
没有合适 owner 时，保存一份明确标记状态的 PRD。
业务项目的现状文档与待实现提案必须区分，不能把提案写成已上线事实。
用户要求「技能试跑」时，试跑材料与通用 skill 分离；不得把个案阈值、股票、
业务名、数据源或自动化偏好写成通用规则。

按任务需要覆盖以下信息，简单需求可以合并章节：

- 状态、主任务/试跑任务、目标、非目标、成功信号。
- 当前事实与来源快照；仅查过源码不能声称核实了生产。
- 本次产品变更：对每项核心要求说明当前行为/缺口、目标行为、需复用或补齐的能力及对应验收。
  新需求说明新增行为即可；现状未核实就标未知，不编造 before/after，不以功能口号代替变化。
- 用户主线、入口、关键分支、操作文案及其行为。
- 数据/判断/动作合同；预测与实际、准入与排序分开。
- 已确认选择和理由；弃选方案不再作为当前要求。
- 首个真实任务、已知变化场景和关键失败路径的可观察验收；每项绑定输入、通过条件、
  证明方法、环境、模拟边界、前置条件及证据状态（计划/已验证/未验证/失败），不以数量代替效果。
- 存量数据/任务如何处理；如果不涉及就注明不适用。
- 未决问题，区分阻塞产品决定与待实现方案核实的技术事实。

不要为了填模板发明数据指标、性能目标、架构、表结构或未来功能。
PRD 可以指出需复用的产品能力或 owner 证据，但不替 devflow 冻结模块和实现 slices。
验收应证明对应的产品变化；具体文件、函数、schema 和测试接口留给实现设计，不能以此为由省略产品行为。

## 收口证据

读取[门槛记录与校验](gates.md)。记录放在同一PRD的一个附录，引用正文而不复制第二份事实真源。
只写草稿时可保留blocked；内容评审和ready校验都通过后才可建议整体确认或交接。
已确认的产品目标保持不变，技术实现检查留给devflow；提前知道的外部验收条件必须随需求交接。
没有保存授权时保持会话草稿，通过stdin校验，不为执行门槛创建项目文件。

## 确认依据

在 PRD 的一个位置保留简短批准记录：决定、用户原话摘录和后续明确变更。
无需复制完整聊天；没有真实时间戳或消息 ID 时不编造。
后来改变决定时追加变更依据，不把原批准改写成用户一开始就同意新规则。
未确认的建议要保留为建议；不把旧方案混进规范部分。
后续文档只引用此记录，不复制第二份批准真源。

## 交接最小内容

短任务可以在 PRD 末尾附交接块；需要独立交接文件时只引用 PRD，不复制整份需求。

- 根目标、当前任务、PRD 路径和批准记录位置。
- 已确认的 scope / success signals 引用，以及尚未完成的下一动作。
- 接收项目路径、当前事实的 commit/文件依据；下一会话要刷新漂移证据。
- 已获准与未获准的行为，阻塞项和需要向用户返回的决定。
- 当前验证及其局限，不把需求 walkthrough 写成实现测试；给出同版本门槛记录和复验命令。
  未做真实效果验收时，交接其条件与负责人，不把本地实现通过写成产品效果已达成。
- 读取接收方可用 skill 后确认正确入口。

与 devflow 的映射：
- 已落盘时给出真实 `prd_doc` 路径；只读模拟或仅会话草稿时注明未落盘并引用当前材料，不虚构路径。
  `design_doc` 尚未产生时应明确为空。
- 已有需求批准可作为 Brainstorm 输入，不能谎称 devflow 的 Brainstorm 或 Save Design 已通过。
- 保存 PRD 不触发 Save Design 后的自动 Panel；准备交接不启动任何后续 gate。
- 不提前承诺 Planreview/Deepreview 的次数、评审人或具体实现方案，读取接收方实际规则。
- 真正进入 devflow 后才依其约定维护 Devflow Progress；handoff_prepared 不是 workflow completed。
- 实现设计发现约束冲突时应带证据返回产品决定，不能通过削弱验收满足方案。

## 自查

能否只读这份交接材料和所指 PRD 就继续工作，而不用猜会话历史？
是否把根任务（例如设计 prdflow）误换成案例任务（例如实现 Wheel）？
是否把用户确认的产品目标与实现、外部写入、安装或交付授权混为一谈？
