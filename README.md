# liuxie-skills

**和 AI 一起，把想法做成产品。**

面向非技术背景的产品创造者，两个 Skills：**PRDflow** 帮你把需求想清楚，**Devflow** 帮你把需求做出来。

从一个具体问题开始：你想为谁做什么，他们现在遇到了什么困难。你负责目标、取舍和体验，AI 帮你整理需求、设计方案、编写代码和检查结果。

## 两个 Skills，一条产品路径

### PRDflow · 把想法变成清楚的需求

有一个模糊想法，可以从讨论开始；已经聊过很多，也可以直接整理成稿。需求变化时，继续修改同一份文档。

PRDflow 帮你回答：

- **给谁用？** 用户遇到了什么问题，为什么需要这个产品。
- **怎样用？** 用户从哪里开始，经过哪些操作，最后得到什么。
- **先做什么？** 第一版的范围，以及这次暂时不做的事情。
- **怎样算做成？** 用哪些具体操作判断结果符合预期。

产出是一份可以阅读、讨论和验收的产品需求文档（PRD）。尚未确定的事情会明确标出，留给你继续判断。

[查看 PRDflow](skills/prdflow/SKILL.md)

### Devflow · 把需求推进到可以验证的实现

带着确认过的需求开始开发，也可以从已有设计或改动继续。

```text
澄清目标 → 保存设计 → 优化设计 → 实现功能 → 审查结果
```

这五步既可以组成完整流程，也可以单独使用。例如，先讨论方案，或只审查已经写好的代码。设计优化会收集四份独立建议，再结合目标和证据判断哪些值得采纳。

Devflow 会说明方案取舍、落实已确认的改动、运行相关验证，并交代做了什么、怎样检查、还有什么未完成。需要你决定的事项会说明影响和建议。

[查看 Devflow](skills/devflow/SKILL.md)

## 从你的第一个小产品开始

下面以 Codex 为例。Skill 是交给 AI 的工作指南，需要在支持 Skills、能读写项目文件和运行命令的工具中使用。

### 1. 安装

在 Codex 对话中发送：

```text
$skill-installer 从 https://github.com/liuxie066/liuxie-skills 的 main 分支安装
skills/prdflow 和 skills/devflow 两个 Skill。
如果已有同名项，先核对版本，不要直接覆盖。
```

安装后在下一轮对话中使用；若没有出现，重启 Codex 后再试。详见 [OpenAI 官方安装说明](https://learn.chatgpt.com/docs/build-skills)。只需要梳理需求时，也可以先安装 PRDflow。

### 2. 说出你想解决的问题

在 Codex 中打开用于存放产品的项目文件夹，然后发送自己的想法。下面是一个练习示例：

```text
$prdflow 我想做一个自己用的内容选题工具。
我经常把想法记在不同地方，写内容时又找不到。
第一版希望能新增选题、标记待写或已完成，并按状态筛选。
我不懂编程，请用容易理解的话，和我一起明确需求与验收方法。
```

围绕草稿讨论和修改。确认符合你的想法后，再让 AI 保存：

```text
这份需求已确认，请保存到 docs/prd.md。
```

### 3. 开始做，并亲自试用

```text
$devflow 按 docs/prd.md 推进第一版的设计、实现和审查。
请先建议合适的流程，解释需要我决定的事项。
完成后告诉我怎样运行、测试了什么，还有什么没做完。
```

Devflow 会根据项目情况建议简单或完整流程，由你选择。两种流程都保留设计优化、实现验证和审查。

拿到结果后，按需求亲自试用：新增一个选题、改成已完成、切换筛选条件。如果约定了保存，再关闭并重新打开，看看内容和状态是否还在。遇到不符合预期的地方，把操作过程和实际结果交给 AI 继续处理。

**完成的标准，是你能用它做好约定的事情。**

## 适用范围

可以从个人网站、内容工具、报名页面或工作中的小工具起步，先完成一个有用的版本，再根据实际使用改进。

PRDflow 负责需求，Devflow 负责研发；产品是否上线、使用哪些付费服务、授予哪些账号权限，仍由你决定。Devflow 的四路设计优化需要工具支持多代理协作；具体项目的依赖和运行条件由 AI 核查，未完成的验证应明确说明。
