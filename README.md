# liuxie-skills

**帮助非技术背景的人，和 AI 一起把想法做成可以使用的产品。**

你可能知道自己想解决什么问题，却不知道怎样把想法说清楚、从哪里开始开发，或者怎样判断 AI 做出来的东西是否符合预期。

liuxie-skills 把这些工作整理成可重复使用的 Skills：先明确需求，再形成方案、实现功能、检查问题，最后用真实操作验收。你负责目标、取舍和体验，AI 帮你组织需求、编写代码并提供验证证据。

适合从一个小产品开始：个人网站、内容选题工具、报名页面，或自己工作中反复用到的小工具。

## 它怎样帮你

Skill 可以理解为交给 AI 的一份工作指南，告诉它如何推进一类任务、什么时候需要你做决定、怎样检查结果。本项目以 Skills 形式使用，需要支持它们的 AI 编程工具。

| 你遇到的问题 | 使用哪个 Skill | 你应该得到什么 |
| --- | --- | --- |
| 有想法，但说不清第一版要做什么 | [PRDflow](skills/prdflow/SKILL.md) | 一份能读懂的需求文档：给谁用、怎样使用、先做什么、如何验收 |
| 需求明确了，希望开始做产品 | [Devflow](skills/devflow/SKILL.md) | 经过方案讨论、实现、测试和代码审查的改动，以及实际完成情况 |
| 想先检查方案有没有遗漏 | [Planreview](skills/planreview/SKILL.md) | 方案中的问题、影响与调整建议 |
| AI 写好了，想检查代码问题 | [Deepreview](skills/deepreview/SKILL.md) | 有依据的代码审查结果与未解决风险 |
| 技术解释听不懂，想看图理解 | [Show Me](skills/show-me/SKILL.md) | 围绕当前问题的图解或可视化说明 |

不必记住所有工具。第一次使用，从 **PRDflow → Devflow** 开始即可。

## 开始使用

下面以 Codex 为例。先准备好能读写本地项目、运行命令的 Codex 环境，并打开一个用于存放新产品的项目文件夹。

### 1. 安装起步所需的 Skills

在 Codex 对话中发送：

```text
$skill-installer 从 https://github.com/liuxie066/liuxie-skills 的 main 分支安装
skills/prdflow、skills/devflow、skills/planreview、skills/deepreview。
只安装这四个 Skill；如果有同名项，先告诉我已有版本，不要直接覆盖。
```

安装完成后，在下一轮对话中使用。若没有出现，重启 Codex 后再试。安装及发现机制参见 [OpenAI 官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills)。

只需要整理需求时，可以先只安装 `skills/prdflow`。每个 Skill 都应安装整个目录，包含它引用的资料与脚本。

### 2. 用自己的话描述想做的产品

下面是一个练习示例，你可以换成自己的问题：

```text
$prdflow 我不懂编程，想做一个自己用的内容选题工具。
我经常把想法记在不同地方，写内容时又找不到。
第一版希望能新增选题、标记待写或已完成，并按状态筛选。
请用普通人能理解的话，帮我明确第一版范围和验收方法。
```

和 AI 一起修改需求，直到你能判断：它解决了谁的什么问题，用户怎样完成任务，哪些事情这次先不做。PRD 就是把这些共识写下来的需求文档。

确认后，可以继续说：

```text
这份需求符合我的想法，请保存到 docs/prd.md。
```

### 3. 从需求推进到实现

```text
$devflow 按 docs/prd.md 帮我实现第一版。
我没有技术背景，请解释需要我决定的事项，给出建议和理由。
先说明准备怎么做，以及怎样验证它符合需求。
```

Devflow 会根据项目情况建议简单或完整流程，由你选择；两种流程都要求方案检查、实现验证和代码审查。需求文档是输入，开始开发时仍会核对实际项目情况。

完成后，请它给出运行方法、验证结果和未完成事项。按刚才的选题工具示例，你可以亲自检查：

- 新增一个选题后，它是否出现在列表里。
- 标记为已完成后，筛选结果是否随之变化。
- 如果需求约定了保存，关闭并重新打开后，选题和状态是否仍然正确。

界面出现了，只是开始；你能完成约定的任务，才是验收的依据。

## 使用前需要知道

- **从小范围开始。** 第一版先完成一个明确任务，后续根据实际使用再增加功能。
- **保留你的决定权。** 涉及产品取舍、付费服务、账号权限或上线目标时，看懂影响再决定；可以随时要求 AI 用具体例子解释。
- **运行条件取决于工具与项目。** Devflow 的设计讨论需要宿主支持多代理协作；具体项目也可能需要安装依赖或连接服务。缺少能力时应报告阻塞，不能把未执行的检查说成通过。
- **开发完成与上线分开。** PRDflow 负责需求，Devflow 负责研发；提交、发布和部署需要另外明确安排。
- **按需安装。** 当前公开入口是 Skill 源文件，尚未提供一键产品构建应用。其他目录包含不同用途的工具，使用前阅读对应说明；不要将根目录的维护脚本当作安装器运行。
